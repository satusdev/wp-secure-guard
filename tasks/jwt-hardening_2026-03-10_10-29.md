# Task: JWT Token Support + Auth Loop Stabilization

## Status

- IMPLEMENTED_PENDING_RUNTIME_VERIFICATION

## Task

Add JWT bearer token support (HS256) with short TTL and denylist revocation,
remove static token auth paths, and remove duplicate/loop-prone auth paths in
REST fallback handling.

## Context

- Existing plugin uses static opaque bearer tokens stored as SHA-256 hashes.
- Sensitive endpoint blocking, route/IP/rate checks, and logging already exist.
- User requested JWT support and fixes for issues/loops.

## Plan

1. Add JWT dependency and loader integration.
2. Extend token persistence model for token type and JWT revocation metadata.
3. Implement JWT validation path in token manager (HS256 + claim checks).
4. Integrate JWT-only auth flow in REST guard preserving existing policy checks.
5. Remove duplicate fallback route/auth validation loops.
6. Extend admin token/settings UI for JWT controls.
7. Update source-of-truth documentation and run verification.

## Risks

- Key/claim misconfiguration can lock out API clients.
- Stateful denylist increases DB writes and requires cleanup strategy.
- Existing clients using legacy static tokens are immediately invalid after
  cutover.

## Verification

- PHP syntax checks for all modified files.
- Verify legacy static token flow is rejected.
- Verify JWT allow/deny cases (signature, exp, iss/aud, revoked jti).
- Verify fallback auth no longer performs duplicate validation loops.
